# 微信云开发配置

小程序端和 H5 端连的是**同一个云开发环境**，所以下面只需要配一次。

## 一、创建环境

1. 打开微信开发者工具，导入项目（`dist/dev/mp-weixin`）
2. 顶部工具栏点「云开发」→ 开通
3. 创建一个环境（开发阶段用**免费环境**即可；未上线阶段无需续费）
4. 记下**环境 ID**（形如 `mapbook-1g2h3j4k`），填进 `.env` 的 `VITE_CLOUDBASE_ENV_ID`

## 二、创建集合

云开发控制台 → 数据库 → 新建集合，建两个：

- `trips`
- `waypoints`

### 权限设置（关键）

两个集合的权限都设为 **「仅创建者可读写」**。

这一条等价于原来 PostgreSQL 里的 RLS 策略：云开发会自动把调用方的 openid
写入文档的 `_openid` 字段，并把读写范围限制在自己创建的数据内。
**不需要写任何额外的鉴权代码。**

> 其他三个选项（所有用户可读、仅创建者可写、所有用户不可读写）都不适合本场景。

### 建议索引

数据量大之后加这两个索引可以显著加快查询：

| 集合 | 索引字段 |
|---|---|
| `trips` | `updated_at`（降序） |
| `waypoints` | `trip_id`（升序） + `day_index`（升序） + `order_index`（升序） |

## 三、数据模型

云开发是文档型数据库，没有 JOIN、没有级联删除，所以采用**两张扁平集合 + 应用层关联**。

### `trips`（路书）

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 主键。由**客户端生成**（便于 upsert），云开发也接受 |
| `_openid` | string | 创建者 openid，云开发自动注入，**不要手动写** |
| `title` | string | 标题 |
| `description` | string | 描述 |
| `day_count` | number | 天数，至少 1 |
| `status` | string | `draft` \| `published` |
| `start_date` | string | `YYYY-MM-DD`，可空字符串 |
| `end_date` | string | 同上 |
| `cover_lng` / `cover_lat` | number \| null | 封面地图中心 |
| `cover_zoom` | number | 封面缩放级别 |
| `created_at` | number | 毫秒时间戳 |
| `updated_at` | number | 毫秒时间戳 |

### `waypoints`（地点）

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 主键，客户端生成 |
| `_openid` | string | 自动注入 |
| `trip_id` | string | 关联 `trips._id`（业务外键，云开发不校验） |
| `day_index` | number | 第几天，从 1 开始 |
| `order_index` | number | 天内排序，从 0 开始 |
| `name` | string | 地点名 |
| `address` | string | 地址 |
| `lng` / `lat` | number | 坐标（GCJ-02） |
| `poi_id` | string | 高德 POI ID，可空 |
| `type` | string | `departure` \| `destination` \| `waypoint` \| `lodgment` \| `dining` |
| `notes` | string | 备注 |
| `created_at` | number | 毫秒时间戳 |

### 与旧 PostgreSQL schema 的差异

- 删掉了 `routes` 表：路线始终实时计算，缓存层从未被使用
- 删掉了 `user_id`：由 `_openid` + 权限规则替代
- `trips` / `waypoints` 之间**没有级联删除**，删除路书时由应用层先清理名下的地点
  （见 `src/services/backend/cloud-crud.ts` 的 `deleteTrip`）

### 两个必须注意的限制

1. **客户端单次查询有上限**：小程序端 100 条，Web 端 20 条。
   代码里统一按每页 20 条翻页取全量（`PAGE_SIZE`），新增查询时不要漏掉分页。
2. **没有批量 upsert**：`saveWaypoints` 是逐个 `doc(id).set()` 的。
   地点数量大的场景需要改成云函数。

## 四、H5 端额外配置

H5 通过 `@cloudbase/js-sdk` 连同一个环境，需要额外两步。

### 1. 开启登录方式

云开发控制台 → 环境 → 登录授权 → 开启**邮箱登录**，并配置 SMTP 发信
（QQ 邮箱、腾讯企业邮箱均可）。

> 不想配 SMTP 的话，可以改用「用户名密码登录」，无需邮件验证。
> 这时要把 `src/services/backend/impl-cloudbase.ts` 里的 `signUp`/`signIn`
> 换成对应的 SDK 方法。

### 2. 配置 Web 安全域名

云开发控制台 → 环境 → 安全配置 → Web 应用 → 添加安全域名，
把 H5 部署的域名加进去。本地开发加 `localhost`。

### 3. H5 的地图需要腾讯地图 Key

H5 端的 `<map>` 组件由 uni-app 用**腾讯地图**实现，和逆地理/路径规划用的高德
是两套东西（坐标都是 GCJ-02，能对齐）。

在 `src/manifest.json` 里填腾讯地图 Key：

```json
"h5": {
  "sdkConfigs": {
    "maps": {
      "qqmap": { "key": "你的腾讯地图Key" }
    }
  }
}
```

申请：[腾讯位置服务控制台](https://lbs.qq.com/dev/console/key/manage)。
**小程序端不需要这个**——小程序用的是微信原生 `<map>` 组件，不需要任何 Key。

## 五、常见问题

**`VITE_CLOUDBASE_ENV_ID 未配置`**
`.env` 没填，或改完 `.env` 后没有重启开发服务器（Vite 只在启动时读 env）。

**小程序里请求全部失败**
确认开发者工具「详情 → 本地设置」里勾了「不校验合法域名」。
上线前必须把 `restapi.amap.com` 加到小程序后台的 request 合法域名。

**`高德接口报错 10009`**
Key 平台类型不对，必须是「Web服务」，不能是「Web端(JS API)」。详见 SETUP.md。

**H5 里地图区域空白**
`manifest.json` 的 `h5.sdkConfigs.maps.qqmap.key` 没填，见上面第四节第 3 点。

**读到 0 条数据但集合里明明有**
检查集合权限是不是「仅创建者可读写」——用另一个 openid（比如换了账号）是读不到别人数据的。

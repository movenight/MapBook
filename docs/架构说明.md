# MapBook 架构说明

本文说明「小程序 + H5 双端」的实现方式，以及上一版纯 Web 实现（Vue 3 + Element Plus +
Supabase + 高德 JSAPI）的对应关系。旧实现仍可在 git 历史里查阅。

## 一、双端怎么共用一份代码

```
                    src/  （唯一源码）
                       │
        ┌──────────────┴──────────────┐
        ▼                             ▼
  uni build -p mp-weixin        uni build
        │                             │
   dist/build/mp-weixin           dist/build/h5
   （微信开发者工具导入）          （浏览器）
```

三处差异被显式收敛，业务代码无需感知平台：

| 差异点 | 收敛位置 | 手段 |
|---|---|---|
| 后端 SDK（`wx.cloud` vs `@cloudbase/js-sdk`） | `src/services/backend/` | `#ifdef` 条件编译 + 统一 `Backend` 接口 |
| 地图渲染（原生 `<map>` 组件） | `src/components/map/MapView.vue` | 同一个组件，两端由 uni-app 各自实现 |
| 登录流程（小程序无登录 / H5 邮箱登录） | `impl-*.ts` 的 `requiresLogin` | 页面守卫读这个标志决定是否跳登录页 |

### 条件编译

`src/services/backend/index.ts` 里，各平台的实现用 `#ifdef` 包住：

```ts
// #ifdef MP-WEIXIN
import { wxCloudBackend } from './impl-wxcloud'
// #endif

// #ifdef H5
import { cloudbaseBackend } from './impl-cloudbase'
// #endif
```

编译时无关分支会被整段删除。**已验证**：小程序产物里搜不到 `cloudbase`
（`@cloudbase/js-sdk` 是浏览器专用包，混进去会显著增大体积甚至报错）。

## 二、后端适配层

`Backend` 接口（`src/services/backend/types.ts`）是业务代码唯一依赖的数据访问契约：

```ts
interface Backend {
  platform: 'mp-weixin' | 'h5'
  requiresLogin: boolean
  getCurrentUser(): Promise<AuthUser | null>
  signIn(email, password): Promise<AuthUser>
  signUp(email, password): Promise<AuthUser>
  signOut(): Promise<void>
  listTrips(): Promise<Trip[]>
  getTrip(id): Promise<Trip | null>
  saveTrip(trip): Promise<Trip>
  deleteTrip(id): Promise<void>
  listWaypoints(tripId): Promise<Waypoint[]>
  saveWaypoints(waypoints): Promise<void>
  deleteWaypoints(ids): Promise<void>
}
```

分成三块：

- **`cloud-crud.ts`** —— 增删改查逻辑只写一份，两个平台共用。
  它依赖一个极小的 `CloudDb` 抽象（`collection/where/orderBy/limit/skip/get/doc/set/remove`），
  两端的数据库 SDK 形状基本一致，各自适配一下即可。
- **`impl-wxcloud.ts`** —— 小程序。`wx.cloud.init()` 之后直接用，
  openid 由云开发隐式注入，所以 `requiresLogin: false`，没有登录流程。
- **`impl-cloudbase.ts`** —— H5。`@cloudbase/js-sdk` v3 是模块化的，
  必须显式 `registerAuth(app)` + `registerDatabase(app)`，否则 `app.auth()` /
  `app.database()` 是 `undefined`（主包不会自动挂载）。

### 字段映射集中在一处

`mappers.ts` 是唯一的 `camelCase ↔ snake_case` 转换点。上一版因为映射分散且只做了单向，
直接导致两个 bug（见第四节）。

### 关于 ID 生成

所有 `_id` 由客户端用 `generateId()` 生成（时间戳 + 随机串），而不是等云开发返回。
好处是 `doc(id).set()` 天然就是 upsert，**不需要区分「新建」和「更新」两条路径**。
`crypto.randomUUID()` 在小程序里不可用，也是换掉它的原因之一。

## 三、地图方案

小程序里没有 DOM，高德 JSAPI 完全不可用。改成「原生 map 组件渲染 + 高德 Web 服务取数据」：

| 能力 | 旧 Web 实现 | 现在 |
|---|---|---|
| 地图渲染 | `new AMap.Map(div)` | uni-app `<map>` 组件 |
| POI 搜索 | `AMap.AutoComplete` | `uni.request` → `/v3/assistant/inputtips` |
| 逆地理编码 | `AMap.Geocoder` | `uni.request` → `/v3/geocode/regeo` |
| 驾车路线 | `AMap.Driving` | `uni.request` → `/v3/direction/driving` |
| 路线绘制 | `AMap.Polyline` | `<map :polyline>` |
| 标记 | `AMap.Marker` + emoji label | `<map :markers>` + 生成的 PNG 图标 + callout |
| 右键菜单 | `rightclick` 事件 | 点击地图 → 弹类型选择面板 |

几个实现要点（都在 `src/components/map/` 里）：

- **坐标系方向**：高德返回 `"lng,lat"` 字符串，`<map>` 的 polyline 要
  `{latitude, longitude}`。转换收敛在 `services/amap/route.ts`，组件层不用管。
- **marker.id 必须是数字**：`@markertap` 只回传这个数字，所以 `MapView` 维护了
  「数字序号 → 业务 id」的映射，把数字当数组下标用。
- **路线抽稀**：高德返回的 polyline 可能上万个点，小程序渲染会卡。
  超过 600 点时按步长抽稀（`route.ts` 的 `downsample`），保证终点不丢。
- **marker 图标**：小程序 marker 的 `iconPath` 需要真实图片，不支持 SVG / emoji。
  图标由 `scripts/gen-marker-icons.mjs` 用 zlib 直接手写 PNG 生成，5 种类型 5 个配色。
- **路线规划失败不静默**：退回虚线直连，并在图上显示失败原因
  （最常见就是高德 Key 平台类型不对，报 10009）。

### 界面布局的调整

原来是「桌面左右分栏（侧边栏 + 地图）」，手机上没有这个空间。改成：

```
┌─────────────────────┐
│  搜索栏（独立一行）   │  ← 不放浮层：小程序 <map> 是原生组件，
├─────────────────────┤     盖在它上面的普通 view 不可靠
│                     │
│      全屏地图        │  ← 搜索出结果时整块换成结果列表，
│                     │     而不是做下拉浮层
├─────────────────────┤
│  抽屉把手（摘要行）   │  ← 默认收起，符合「地图优先」
│  ─────────────      │
│  展开后：标题/描述    │
│  + 按天地点列表       │
│  + 添加新的一天       │
├─────────────────────┤
│ 总距离 / 总时长 / 状态 │
└─────────────────────┘
```

抽屉是**普通流内元素**（在 flex 列里占位），不是浮层——同样是为了避开原生组件的层级问题。

## 四、顺带修掉的 3 个旧 bug

重构时发现的真实缺陷，都已修复：

1. **途经点从未写入数据库**（最严重）
   旧代码里 `db.upsertWaypoints` 是死代码，`saveCurrent()` 只写了 `trips` 表。
   结果是刷新页面后所有地点全部丢失。
   现在 `tripStore.persist()` 会同时写路书和地点。

2. **删除某天后天数不重排**
   旧 `removeDay` 只递减了 `dayCount`，没有把后面的天前移，会出现
   Day 1 / Day 3 这种空洞。现在会整体重编号。

3. **总距离/总时长在多天时互相覆盖**
   旧代码在异步回调里逐个赋值 `totalDistance`，多天时 last-write-wins。
   现在按天存进 `routeByDay`，总距离/总时长由 computed 求和，不再有竞态。

另外一并处理的：路由守卫缺失（旧 `meta.requiresAuth` 从未生效，现在由各页
`userStore.requireLogin()` 兜住）、`AppHeader` 登录态不响应（改用 `userStore`）、
`crypto.randomUUID` 不可用（换自研 `generateId`）、地点类型图标不统一
（旧侧边栏漏了 `dining`，现在统一走 `WAYPOINT_TYPE_ICONS`）。

## 五、跨端样式踩坑记录

写新组件时注意这三条（`src/uni.scss` 里也有注释）：

1. **页面满高不要写 `100vh`**。H5 下页面内容区在导航栏之下，`100vh` 会多出
   一个导航栏高度把内容顶出视口。用：
   ```scss
   height: calc(100vh - var(--window-top, 0px) - var(--window-bottom, 0px));
   ```
   `--window-top` / `--window-bottom` 在 H5 有值，小程序里回退 `0px`，两端都对。

2. **`uni.scss` 里只放变量，不要放 mixin**。它只被注入到组件样式的变量作用域，
   组件里 `@include` 会报 `Undefined mixin`。需要复用的样式写进组件自己的 `<style>`。

3. **`<text>` 默认是 `inline`**。竖排文本要显式 `display: block`，
   否则会挤成一行且 `margin-top` 失效。放在 flex 容器里的不用管（会被 blockify）。

## 六、已知取舍（V1 有意为之）

- **不采集微信昵称头像**：只用 openid 做身份，避免隐私协议审核成本。
  界面上不展示用户信息。
- **不调用 `wx.getLocation`**：用搜索和点击地图代替，规避位置权限审核。
- **没有云函数**：删除路书时用客户端循环删地点。地点数量大之后应改成云函数。
- **路线不缓存**：每次都实时调高德。产品规划里的 `routes` 缓存表从未实现，
  这一版也没做。
- **不迁移旧数据**：从空库开始（原 Supabase 项目当时已失效）。
